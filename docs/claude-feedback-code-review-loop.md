После каждой задачи прогоняй `code-reviewer` agent **в цикле**, не один раз. Каждое замечание сначала сверяй с задачей, фактическим кодом и правилами проекта. Подтверждённые замечания исправляй и **снова** запускай ревьюер. Ложные или неприменимые отклоняй с кратким обоснованием. Повторяй, пока не останется 0 подтверждённых замечаний. Только после этого задача считается готовой к сдаче пользователю.

**Why:** Дмитрий явно попросил это после того как я в задаче «Карточка товара» прогнал ревью один раз, исправил замечания, но не перепроверил — а в требованиях на качество уровня dorogix компаний должна быть гарантия что после правок всё чисто. Один прогон не гарантирует что правки не внесли новых проблем.

**How to apply:**
- После имплементации фичи → запустить `code-reviewer` agent
- Если **есть подтверждённые замечания** любого уровня → исправить → повторить затронутые тесты → **снова** прогнать `code-reviewer`
- Если **0 подтверждённых замечаний** → коммит → отчёт пользователю «готово»
- Не пропускать подтверждённые «минорные» замечания между итерациями
- После исправления первой пачки и нового прогона может всплыть что-то новое (например, я мог что-то сломать своей правкой) — это и есть смысл цикла
- Если менялся UI, после любого следующего видимого изменения повторить итоговый UX-прогон
